## Notes / divergences
First-deploy tooling (tasks 8.1–8.3): tested by `apps/web/test/wrangler-config.test.js` (path rewriting, id insertion, env beats file, missing and malformed id errors that never echo the id, `.gitignore` coverage, workflow and root-script assertions); a dry run of `wrangler deploy --config .local/wrangler.toml` with a dummy id succeeded (bindings `DB` and `ASSETS`, assets directory found).

Divergences from `openspec/changes/archive/2026-10-15-web-checklist/design.md` (none changes behaviour that a spec scenario describes):
- `seed:local` and `seed:remote` run `gen:seed` first and call wrangler through `npm exec -w apps/web`, so the file argument is .local/seed.sql relative to `apps/web`. `migrate:local` was added for the same local flow.
- Deletion markers skip `validateItem` (an item's tombstone must always be storable).
- A wrong method on a known route is 405 (not in the spec; unknown routes stay 404).
- `getState` answers 400 for a malformed `since`.
- `TEAM_DOMAIN` is normalised (scheme added, trailing slash dropped).
- The service worker precaches `/` only (not /index.html): the assets layer answers /index.html with a 307 to `/`, which the install step rejects by design.
- `apps/web/public/view.js` also exports `dayProgress`, `withTick` and `withoutTick`; its `./core/` import is redirected to `packages/core` in tests by `apps/web/test-support/load-view.js` (a `module.registerHooks` resolver), so the source tree is testable without a build.
- The seed statements are `INSERT OR IGNORE`, so re-running a seed never overwrites rows edited since.
- Verified on the real deployment 2026-10-15: all three Access logins, Android install, service worker in desktop Chrome, airplane-mode cold start, two-way tick sync, migration 0002 remotely. Not yet observed: the Access-session-expiry reload in real use, and the GitHub Actions workflows.
